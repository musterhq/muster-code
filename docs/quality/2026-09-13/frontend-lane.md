# Frontend lane · 13 September 2026

Scope: `agent-view.ts`, `agent-polish.ts`, `appearance.ts`, settings webview, Muster themes/icons, workbench skin, and the offline preview harness. The pane remains compatible with the existing `state`, `messages`, `delta`, `tool`, `approval`, `telemetry`, and `done` messages.

## Findings and changes

- The conversation renderer already retained drafts, context, expansion state, and reading position across tab changes. Invalid persisted context is now filtered before it reaches DOM rendering, and malformed message/review/browser payloads degrade to empty collections instead of throwing.
- Run state is now explicit in the activity surface (`Preparing`, `Running`, `Waiting for approval`, `Disconnected`, `Interrupted`, `Complete`, `Ready`). The renderer accepts optional `runState`/`status` fields and optional `events`/`activityEvents`/`timeline` arrays, rendering a bounded activity timeline. Existing `start`, approval, webview error, and `done` events update the state without requiring a runtime change.
- The activity surface accepts optional provider `usageLedger`/`ledger`/`turnUsage` rows and shows input, cached input, output, and reasoning output per turn. Missing fields remain `—`; reported zero remains `0`.
- The context shelf accepts optional `contextRefs`/`contextReferences`/`includedContext` entries and shows source, included range, included line count, source update date, truncation, and token estimate. Existing retained mentions continue to work when the runtime has not sent this richer contract.
- Activity telemetry is persisted with bounded event and ledger history in webview state so switching tabs or recreating the webview does not erase the visible run ledger. Provider history remains authoritative for transcript content.
- Clipboard writes now have a guarded DOM fallback, and settings navigation/toggles are keyboard operable with tab/switch semantics. Appearance settings gained a chat styling reset action and responsive narrow-window layout while preserving all five palettes and native theme/file/product icon controls.
- General settings no longer shows an unbound access selector. Access policy is explicitly labeled per thread, matching the Agent composer and avoiding a misleading global default.
- Rules and MCP switches now emit only their domain toggle message; they no longer fall through to the generic setting writer with an undefined key. Both switch families also expose keyboard activation.
- The chat Masthead includes a compact keyboard accessible Managed terminals action wired to `muster.terminal.workspace`; its fixed width keeps the narrow header usable.
- Muster Graphite is now the native default and the offline fixture palette; the sage, midnight, light, and sand options remain available. VS Code configuration defaults preserve explicit user theme selections.
- Added optional restrained glass styling for isolated webview surfaces (Masthead, composer, activity, menus, Agent workspace). Opaque colors remain the fallback, reduced-motion disables blur, and transcript content receives no gradient/blur treatment. The optional host field is `appearance.glass` with default-on behavior when absent; settings read/write uses `muster.ui.glass`.
- Fixture JSON is now safely serialized before embedding in HTML scripts (`<`, `>`, U+2028 and U+2029 escaped), preventing malicious patch samples from terminating the boot script. Repeated draft persistence now deduplicates host writes while preserving actual text/context changes.
- Glass now uses a genuinely translucent isolated-surface tint with opaque fallbacks for unsupported transparency, reduced transparency, reduced motion, forced colors, and VS Code high-contrast modes. The accent fallback is Graphite violet (`#B0B8F8`); transcript styling remains opaque.
- MC-802 adds an honest, data-driven Agent workspace overlay to the existing chat surface. It now consumes the authoritative versioned `agentWorkspace` snapshot (`nodes`, `events`, `capabilities`), renders selected child details, parent/child events, per-agent changed paths and usage, and enables Stop/Steer only when capabilities allow them. Threads opens the real `muster.thread.catalog` manager entry point. Without graph data it remains an empty state and never invents agent data; action results surface through `agentActionResult` (`reason` is rendered for runtime failures).
- Agent workspace patch inspection consumes node-local additive `changeRecords` keyed by record id, scoped by thread/turn/item/path. Receipts are immutable, escaped, individually expandable, preserved across graph updates and reload, and show explicit missing/truncated guidance with Open thread.
- The offline preview now has `?scenario=agents`, generated through the real `AgentGraphAdapter` with a root, two children, parent follow-up, child status/change/usage events, and deterministic timestamps. It is labeled scripted/no live runtime, disables child controls, and returns explicit action failure text; `state=empty` exercises the empty graph state.
- `scripts/dev/preview-pane.mjs` now supports `?scenario=stress`: deterministic sample data emits 72 messages, 40 activity updates, 80 rapid deltas, 24 context references, and 20 usage rows, with a visible `Stress complete` status marker. It remains offline and keeps the normal typing/context/expansion/scroll controls.
- Stress QA exposed unbounded open activity details pushing the composer offscreen. The activity region now has a viewport-relative cap (`clamp(132px,35vh,360px)`), internal scrolling, sticky summary, and duplicate complete status text suppression; the composer remains reachable at short and narrow heights.
- Nested Included context and Usage by turn disclosure state is now persisted per task and restored after transcript replay/webview recreation. The stress completion marker is fixed to the fixture viewport with wrapping and no pointer capture, so it cannot introduce horizontal overflow.
- Context chips now share a 24px inline-flex control box, 16px icon box, 18px removal target, centered baseline, keyboard focus ring, and wrapping row with bounded vertical scrolling. This keeps Add Context, file references, and browser selections aligned across empty, single, multiple, long, Unicode, and narrow composer states without changing retained-context metadata or removal semantics.
- Activity is compact by default: the main row carries the current action, status, and elapsed time; provider token counts and text-only prompt estimates are available through the explicitly labeled `Usage details` disclosure. The selected model is omitted because it is already present in the composer, and completed/empty activity has no metrics block or verbose explanatory paragraph.
- The task workbench adds a bounded Grid/Split overview over the runtime's versioned `taskWorkspace` registry. It shows named task identity, status, `(taskId, workspaceId, cwd)` ownership, isolated versus serialized checkout capability, reported changes, focused chat, and existing full-file diff/review entry points. A missing thread identity disables chat activation; the scripted fixture never claims concurrent execution.
- Idle surface audit refined the welcome hero into a restrained “What are we working on?” visual anchor, removed its duplicate shortcut row, keeps a direct New task affordance, hides ready/empty activity, and moves Style, Tools, Managed terminals, Browser, and Chat history into a keyboard-accessible More menu. Tasks and Agents remain the two contextual masthead surfaces; composer mode/access/model and full-file review remain visible where their decisions are made. See `docs/quality/2026-09-14/idle-surface-audit.md`.

## Runtime contract request

The runtime now emits the corresponding fields as `run`, `activityTimeline`, `usageLedger`, and `contextReferences` on `state`/`telemetry`; the renderer consumes these contracts while retaining aliases for fixture compatibility. `ActivityRecord` uses `id`, `ts`, `method`/`summary`; `ContextReference` uses `source`, `startLine`, `endLine`, `truncated`, and `tokenEstimate`; `DurableRun.state` drives the run badge. Rich event replay after restart remains a runtime persistence gate; the frontend preserves what it receives and does not invent provider counts. The shared runtime still has a separate typecheck failure in `agent-pane.ts` where `CodexTurnResult` does not declare `turnId`/`dispatchState`.

## Remaining risks

Native Electron smoke checks for live full-file edits, cancellation, dirty buffers, undo/redo, system appearance following, and keyboard/contrast/zoom combinations remain outside this lane and should be covered by the parent integration gate.

The isolated screenshot showed native `Open in Agents Window` and Copilot status in the accessibility tree. The owned stylesheet already scopes visual hiding to Chat/Copilot auxiliary actions and Copilot statusbar IDs; no broader selector was added because those controls may belong to functioning native integrations. Parent should verify exact element ownership before changing them.
